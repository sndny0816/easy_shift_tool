# Sinta 勤務表作成

バージョン **0.6.1**。職員の勤務条件・必要人数・希望休から、担当者が確認するシフト案をExcelへ出力するPythonデスクトップアプリです。

営業実演と条件確認のための初期版です。実際の勤務表として使う前に、担当者の確認が必要です。実行時はローカルで完結し、ログイン、クラウド処理、外部AI API、データの外部送信は行いません。入力原本は変更しません。

## 主な機能

- 日勤のみ／２交代制／３交代制と、区分別の必要人数。
- 曜日・週・日付の出勤率、連続勤務上限、前期間の勤務履歴。
- 確定休、公休希望、有給、日跨ぎ勤務の「明け」の区別。
- 夜勤翌日の新規勤務開始制限と、禁止する勤務区分の順序。
- 公休・有給の配分プレビューと担当者による明示確定。
- 希望が集中する日と申請者を確認するカレンダー。
- 勤務表の手修正、必須条件の再検証、場所・理由・直し方を示すエラー案内。

GUIはtkinter＋ttk、表データはpandas、Excel処理はopenpyxl、計算はOR-Tools CP-SATを使用します。

## 環境構築と起動

Python **3.12**と、Tkが利用できるPython環境、`uv`を用意してください。Pythonの依存範囲は3.12〜3.13ですが、実測した版は下記の「検証範囲」を参照してください。

WindowsではPythonインストーラーの「tcl/tk and IDLE」を有効にします。macOSでもTk付きのPythonを使用してください。**tkinterをpipでインストールしないでください。** 初回の依存関係の導入にはインターネット接続が必要です。

リポジトリのフォルダで実行します。`uv.lock`を使い、依存関係を`.venv`に導入します。

macOS:

```sh
uv sync --python 3.12 --frozen --extra dev
.venv/bin/python -m sinta_shift
```

Windows PowerShell:

```powershell
uv sync --python 3.12 --frozen --extra dev
.venv\Scripts\python.exe -m sinta_shift
```

起動してウィンドウが表示されることを確認してください。Tkの読み込みに失敗する場合は、Python本体とTcl/Tkの導入を確認します。アプリは実在するTcl/Tkスクリプトを検出して検索先を補いますが、Tk本体のインストールを代行するものではありません。

macOSでは初回セットアップ後、`Sinta勤務表を起動.command`をダブルクリックしても起動できます。このリポジトリの`.venv`を使用し、起動時に依存関係をダウンロードしません。

## 操作する順序

1. **「1 Excelを読み込む」**で「Excelを選ぶ」か「サンプルで試す」を押します。先頭20行を確認し、別名のシート・列は「詳しい設定：シート・列名の対応」で対応付けます。形式・列対応と勤務条件は、それぞれJSONへ保存・復元できます。「入力ひな形を保存」も利用できます。
2. **「2 人数と連勤」**で基本の出勤率と連勤上限を設定します。カレンダーの日付や「週全体」から率を変更し、「設定を解除」で基本設定へ戻せます。勤務区分の配分、時刻、禁止順序は「詳しい設定」で確認します。
3. **「3 公休・有給」**で有給にする件数を動かし、配分を確認します。プレビューだけでは確定しません。外部台帳の残高・承認ルールを確認し、「この配分を確定」を押してから「シフト案を作る」を実行します。
4. **「4 シフト確認・保存」**で「勤務表」と「希望休カレンダー」を確認します。勤務表は週送り・全期間表示ができ、セルの区分を変更できます。違反がなければ「結果を保存」で原本と別のフォルダを選びます。同名ファイルは上書きせず連番にします。

「3日分の希望・有給サンプル」では、横形式の独立申請と有給の確認操作を試せます。

## 入力Excel

値の表として保存した **`.xlsx`のみ**を読み込みます。CSV、旧`.xls`、マクロ付きExcel、PDFは対象外です。Excelのシート・見出し行を選択できます。

| シートの役割 | 主な列 |
| --- | --- |
| 職員 | 職員ID、氏名、対象期間の勤務日数 |
| 必要人数 | 日付、配置人数 |
| 確定休 | 職員ID、日付。見出しだけの0件も可。 |
| 希望休（横形式） | 職員ID、希望日1、区分1、希望日2、区分2、希望日3、区分3 |
| 希望休（従来形式） | 申請ID、職員ID、候補日、優先順位。横形式との選択。 |
| 有給（任意） | 職員ID、日付。日付固定の有給。 |
| 勤務条件（任意） | 項目、値。勤務モード・日数方式・連勤など。 |
| 勤務時刻（任意） | 勤務区分、開始時刻、終了時刻、翌日終了 |
| 出勤率調整（任意） | 指定単位（週／日付）、開始日、出勤率％ |

基本は職員・必要人数・確定休・希望休の4シートです。任意の設定シートは所定の見出しで使用します。職員には個別公休日数・前期間の連続勤務日数・前日の勤務区分、必要人数には勤務区分ごとの人数を追加できます。任意列も別名へ対応付けられます。

- 必要人数の日付は対象期間の全日を連続して指定します。日付は`2026-11-07`のように年を含めます。
- IDは文字列です。先頭ゼロと文字列`NA`を保持します。既に数値保存で失われたゼロは推測で補いません。
- 人数・日数は整数、比率は十進数で検証します。空欄・変換失敗を勝手に0へ置き換えません。
- 使用列の数式・Excelエラーを検出して読み込みを止めます。入力用コピーに確認した値を貼り付けてください。
- 職員ID重複、未知ID、期間外の日付、申請の重複、不正な人数・日数、合計の不一致を検出します。

### 横形式と従来形式の違い

横形式は1職員1行です。希望日1・2・3は**3日分の独立申請で、優先順位ではありません**。各枠に日付と「公休希望」または「有給申請」をセットで記入します。「公休」「有給」の表記も使用できます。日付・区分の両方が空欄なら未申請、片方だけならエラーです。

| 職員ID | 希望日1 | 区分1 | 希望日2 | 区分2 | 希望日3 | 区分3 |
| --- | --- | --- | --- | --- | --- | --- |
| 001 | 2026-11-01 | 公休希望 | 2026-11-04 | 公休希望 | 2026-11-07 | 有給申請 |

有給申請は読み込んだだけでは確定しません。未決定が残る間は計算・完成保存を止めます。有給希望を公休希望へ変更すると、その職員の公休目標へ同じ日数を加え、休暇合計を維持します。変更した公休希望は未採用になる場合もあります。元からの固定有給は配分で変更しません。決定状態は設定JSONへ保存せず、新しく入力を読み込むだけで自動承認しません。

従来形式では、同じ申請IDの複数候補は**1日分の休みの代替候補**です。1申請の採用は最大1日で、別申請による同じ休みの重複計上を防ぎます。第2希望の採用・未採用も表示します。

## 計算条件と確認事項

日別の勤務開始人数と区分別人数を指定に一致させ、各人1日1区分、個人の日数条件、確定休・確定有給、設定した連勤・勤務順序を守ります。同日に複数人が休むことも認めます。

出勤率は **日付指定→月曜始まりの週指定→曜日指定→Excel人数**の順で優先します。職員数×比率÷100を切り上げ、区分へは最大剰余法で配分します。同率の余りは区分の表示順です。率を指定した日はExcel人数を変更しても率から再計算されます。

日数方式は「勤務日数を指定」と「公休日数から算出」です。後者では個別または共通の公休枠、有給、明けから勤務を決め、入力勤務日数を独立条件にしません。日跨ぎがなければ30日−公休8日−有給2日＝20勤務です。日跨ぎがある場合は明けを別枠とし、勤務開始回数をこの引き算だけで決めません。

前期間の履歴を使用しない場合は、前日休み・連勤0日と仮定します。実際に前日勤務していた職員の履歴は入力してください。明けは勤務開始人数に含めず、実労働のある暦日として連勤には含めます。

公休・有給・明けを使う交代制では、勤務時刻を確認するまで計算を止めます。日跨ぎ翌日は必ず明けで、夜勤後休みの設定を解除しても新規勤務は入れられません。初期設定は夜勤・深夜勤翌日の新規勤務を禁止し、３交代制では準夜勤→日勤も禁止します。明けのさらに翌日を公休にする条件は自動追加しません。最終日の跨ぎ勤務の翌日は期間外未確認として出力します。

公休希望は、まず採用申請数を最大化し、その件数を維持して候補順位の合計を最小化します。横形式の各申請に優先順位はありません。必須条件を満たすことと希望を全部採用できることは別で、未採用があっても有効な案は保存できます。

| 計算状態 | 意味 |
| --- | --- |
| 最適性確認済み | 採用数と順位合計の最適性を確認。 |
| 実行可能 | 必須条件を満たす案あり。最適性は未確認。 |
| 条件不成立 | 必須条件を同時に満たせないことを確認。 |
| 時間内に案未発見 | 制限内に未発見。案が存在しない証明ではありません。 |
| モデルエラー | 計算モデルを処理できず、案として使用不可。 |

制限時間は初期30秒、画面では最大300秒です。入力検証・モデル構築・2段階探索で共有し、Excel読込・表示・保存は含みません。節目で期限を確認するため、厳密な実時間停止は保証しません。手修正後の最適性も保証しません。

### 希望休カレンダー

その日に希望を出した**異なる職員数**を色と数値で表示します。同じ職員・同日を重複計上せず、従来の代替候補は各候補日に表示します。他候補の採用と申請全体の未採用を区別します。

確定休・確定有給は別表示で、希望人数と重なるため合算できません。色は集中度だけを示し、採否・配置不足・法令適合は意味しません。未計算や条件不成立でも読み込めた希望を確認できます。違反案の採否は参考表示です。このカレンダーはGUI専用です。

## エラーの直し方と保存

エラー行を選ぶと場所・理由・具体的な直し方・次の操作を表示します。原文は技術情報欄で全文を確認できます。行選択だけでは別画面へ移動せず、下部の案内ボタンから修正先を開きます。

| 修正対象 | 次の操作 |
| --- | --- |
| Excelの値・数式 | 原本のコピーを修正して保存し、修正版を選択するか「修正したExcelを再読込」。保存しただけでは画面は更新されません。 |
| 列・シート・見出し | 入力画面の列対応を直して条件確認。 |
| 率・時刻・連勤など | 設定画面で修正し「設定を反映して再確認」。 |
| 未決定の有給希望 | 残高・承認内容を外部台帳で確認し、配分を確定。 |
| 手修正した勤務表 | 該当職員・日付を直し「現在の勤務表を再確認」。Excelは読み直しません。 |
| 保存先・権限 | 案は保持し、書き込み可能な別フォルダで再保存。人数・日数を変更する対処は不要です。 |

入力再読込は、設定シートも含めて案を作り直す操作です。手修正した案の確認と区別してください。「必要2人・勤務可能1人」などの不足では、誤記と実際の配置条件を確認し、確定休や承認済み有給を成立のためだけに解除しないでください。時間内に案未発見の場合は時間を延ばして再実行できます。

結果Excelは「勤務表」「日別人数」「希望休の採用結果」「設定条件」の4シートです。見出し固定・フィルタ・列幅を設定し、件数・条件・採用結果を残します。取り込んだ文字列はExcel数式として出力しません。保存前に再検証し、入力不備や必須条件違反が残る案の完成保存を止めます。出力Excelを外部で編集した内容は自動検証されません。

## 配布用ビルドと構成

Windows版はWindows、macOS版はmacOSでビルドします。上記の開発用依存を導入後に実行します。

```sh
# macOS
sh scripts/build_macos.sh
```

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1
```

手動では仮想環境のPythonで`-m PyInstaller --noconfirm sinta_shift.spec`を実行します。macOSは`dist/Sinta Shift.app`、Windowsは`dist/SintaShift/SintaShift.exe`です。Windowsはフォルダ全体を配布します。ビルド成功と対象PCでの操作確認は別です。

`sinta_shift/`内で、業務データ・検証・計算・再評価・Excel入出力・GUIを分離しています。`tests/`はGUIなしの検証、`scripts/`は起動・GUI検証・ビルドの補助です。

## 対象外

資格別配置、夜勤回数の公平化、総労働時間、休憩・勤務間隔、給与、有給残高更新、半日休・時間休、法令・就業規則適合の自動判定は含みません。時刻は日跨ぎ判定に使い、法律上の休日や休息時間を保証しません。期間外の未来の勤務も検証しません。導入時は職場の追加ルールを確定し、計算と手修正後の検証の両方へ追加してください。
